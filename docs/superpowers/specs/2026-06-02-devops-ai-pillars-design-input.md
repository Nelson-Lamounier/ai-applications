## ⚠️ CORRECTION 1 (FP verdict) — the two-tier claim model is MANDATORY

The report's "SUFFICIENT" labels are sound for *"this artifact exists at file:line"* but **UNSOUND for "your work shows competence in <topic>."** The parsers extract **token-presence only** (verified: `DockerfileParser.ts:9` matches any `FROM x`; `GithubActionsParser.ts:9` any `uses:`; `ArnScanner` any ARN substring). A one-line `FROM nginx`, a `helm create` scaffold, a copied `actions/checkout`, a pasted IAM ARN, an upstream `image: grafana/grafana` in a Helm install — all fire topic signals while proving nothing about competence. **This is the necessary-not-sufficient trap one level up — the same mistake DSA dropped 15 regexes to avoid.**

**Adopted constraint — every DevOps topic splits into two claim tiers:**
- **Tier 1 — ARTIFACT-PRESENT** ("declared/referenced X at `file:line`"): what the parsers actually prove. Always honest. Free from existing extractors. **All 24 "have" mapping rows MUST emit Tier-1 display language.**
- **Tier 2 — TOPIC-COMPETENT**: requires depth markers within the same artifact, e.g.:
  - Docker → ≥2 `FROM` (multi-stage) OR `USER` non-root OR `HEALTHCHECK`
  - K8s orchestration → `livenessProbe`/`readinessProbe` + `resources.limits` + `strategy.rollingUpdate`, or an HPA referencing the workload
  - CI/CD → an authored `run:` test/build/deploy step, `needs:`/matrix/`if:` — not just `uses:` of marketplace actions
  - IAM → an authored policy doc (`aws_iam_policy_document` / multi-statement JSON), not a referenced ARN
  - Observability → authored PrometheusRule PromQL / committed Grafana dashboard JSON / LogQL — not an upstream `image:` tag
  - Helm → `values.yaml` keys actually referenced via `{{ .Values.x }}` + templated probes — not a scaffold
  - Terraform → `backend`/remote-state + `module`/`variable` + same resource type across >1 file, or a TF step in CI
- **Display language rule:** mapping `display_name` MUST say "declared/configured/references X" for Tier 1, NEVER "expert in / knows / your work shows X". Suppress ARN/tech matches found in README/`*.md` prose.

## ⚠️ CORRECTION 2 (scope verdict) — the lane-ownership contract is MANDATORY before any AI work

**AI signal #1 (Bedrock LLM integration) is ALREADY extracted today** — `sdkCallPatterns.json` emits `raw_name: aws_bedrock` from `new BedrockRuntimeClient` into `technology_evidence`. So AI evidence already straddles the tech lane. Without an explicit contract, S4 double-counts Bedrock (once as a skill-graph "technology", once as an "AI practice") — inflating the very honesty the isolation discipline protects.

**Adopted contract:** **tech-extract owns "uses X technology"; `ai_evidence` owns "built X engineering capability"; the two MUST NEVER emit the same artifact.** `AiPatternExtractor` does NOT re-emit Bedrock/pgvector-as-technology — it anchors only on higher-order practice artifacts (cachePoint, grounding-verifier class, eval schema, MCP `tools/call` call site, `recordBedrockCost()` call site, semantic-cache similarity op). This trims the AI detector from ~6 toward ~5 signals.
