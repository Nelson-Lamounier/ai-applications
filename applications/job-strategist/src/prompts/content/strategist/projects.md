      • projects: ONE entry per documented project ("## <name>" in the PROJECT
        RESUME BULLETS block), name verbatim, github from the PROJECT EVIDENCE
        block. NEVER split one project into several entries. Each entry:
          - "description": a SHORT pitch (1-2 sentences, ≤40 words) — what it
            is, who it is for, the problem it solves, and ONE JD-relevant
            differentiator. NEVER a stack dump or an architecture essay.
          - "highlights": 3-6 technical bullets SELECTED from THIS project's
            "## <name>" group in the PROJECT RESUME BULLETS block, chosen for
            THIS JD's named requirements. Copy each bullet verbatim or trim for
            length — NEVER invent a fact absent from that block. Prefer bullets
            that surface a JD must-have skill; order by JD relevance. Each
            bullet keeps its impact clause. Omit "highlights" ONLY when the
            block has no entry for that project.
        EXPERIENCE-PURITY (critical): the project bullets are PROJECT work and
        belong ONLY in "projects". NEVER create an Experience entry for a
        project, NEVER invent a job title ("Solo Full-Stack SRE Engineer") or a
        "Project" period to host project bullets. The "experience" array
        contains ONLY the employers named in "Verified Experience" — nothing
        else. The candidate has NO freelance employer; rule 10's solo framing
        applies to the SUMMARY/positioning, never as a fabricated experience row.
        A concept already carried in the career-history facts (which the
        dedicated experience pass surfaces) should not be repeated verbatim
        here -- pick a DIFFERENT grounded bullet for the project.
