## What this means

**The L1 extractors are producing massive signal.** They scan source aggressively and emit raw tokens at ~1k–2k extractions per repo. **The resolver canonicalises only 14-24% of that signal.** The deterministic + LLM ontology growth (96 → 2467) populated *canonical entries* but left the alias graph thin for the variants L1 actually emits — particularly scoped npm packages (`@aws-cdk/cloud-assembly-api`, `@aws-sdk/client-ssm`, `@nestjs/core`), namespaced Helm charts, dotted Maven coords, and case/separator variants.

## Strategic re-read (validates the user's framing)

Alias coverage is the leverage. Every alias added retroactively resolves all matching unresolved evidence across every repo (if the backfill worker exists; otherwise on next re-run). Detectors only help future extractions.

Two concrete fix surfaces:

1. **Bulk alias backfill for scoped/namespaced packages.** L1's `syft` and `treesitter` layers emit:
   - `@aws-sdk/client-*` (~10-20 variants)
   - `@aws-cdk/asset-*`, `@aws-cdk/cloud-assembly-*` (~5 variants)
   - `@nestjs/*`, `@apollo/*`, `@tanstack/*`, `@testing-library/*`, etc.
   - `aws-cdk-lib`, `aws-cdk` (variants of `aws_cdk`)
   These need either (a) one canonical per scoped pattern with aliases for each concrete variant, or (b) a "scoped-namespace alias rule" (e.g. anything matching `^@aws-sdk/client-(.+)$` resolves to `aws_<group>` if a canonical exists). The latter is a resolver enhancement; the former is bulk data work the candidate-review loop should handle.
2. **`ArgoHelmParser` coverage check for the observability stack.** Zero raw evidence for grafana/loki/prometheus/etc. on the infra repo means the parser either didn't run on the right files or doesn't extract chart-dependency names. Worth one trace through `ArgoHelmParser.parseHelmChart` against `kubernetes-bootstrap/charts/monitoring/chart/Chart.yaml`.

## Proposed decommission gate

In line with the user's framing, **replace the single `recall ≥ 0.85` number** with a bucketed criterion:

- **Bucket (a) + (b) closure**: ≥ 90% of source-extractable LLM-only entries closed (after alias backfill + targeted detector fixes).
- **Bucket (c)**: enumerated and accepted as known carve-out (cluster-deployed infra, externally-managed services).
- **Bucket (d) and (e)**: explicit policy applied to both ontology and comparison; excluded from the denominator.

Recall number that satisfies these criteria will fall out of the work — likely 0.65–0.80 against the *adjusted* denominator (LLM canonicals minus (d) and (e) and accepted (c)).

## Policy proposal for bucket (e) — IN scope unless

Build tools, package managers, linters, test frameworks, formatters, type definitions ARE technologies for skill-extraction purposes. They demonstrate toolchain competence and are commonly listed on engineering resumes. **Exclude only:** wire-level protocols and generic algorithms with no implementation choice (`http`, `https`, `tcp`, `json`, `base64`, `sha256`, `hmac`, `url`, `uuid`, `cors`). Everything else is signal.
